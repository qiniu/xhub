# 续聊历史存储优化

## 目标与范围

统一 Responses 续聊需要恢复之前的消息、工具调用和上游不透明内容。历史目前按每个响应保存完整数组，长对话可能反复存储前文。本方案保留完整语义，按调用方、公开模型和入口隔离消息块；相同范围的相同消息复用块，每个响应另存有序摘要。较大消息块使用无损压缩，读取时验证长度和摘要。原生透传的归属、权限、预算和日志保留规则不变。

## 运行方式

程序启动时创建新增的 `conversation_history_blocks` 和 `conversation_history_manifests` 表，始终能读取旧 `kv` 历史和新格式。默认继续写旧格式。设置进程环境变量 `XHUB_COMPACT_HISTORY=1` 后，新产生的统一 Responses 历史使用新格式；移除开关后新写入回到旧格式，已生成的新格式仍由支持它的版本读取。开关是进程级配置，变更需重启进程。

内容块与索引在同一事务提交。响应历史或归属保存失败时，统一 Responses 不发布成功终态；已有数据帧的流将收到失败事件。固定上游归属和认证隔离仍由现有路由计划检查。历史块缺失、压缩错误、摘要错误或范围不符时，续聊明确失败，不使用旧副本掩盖故障。

## 旧历史迁移

旧键是包含调用方等信息的不可逆摘要，无法可靠恢复跨响应的原始隔离范围。迁移器因此给**每条旧记录**单独设置范围，保留旧副本并逐条重建验证；它不会因为会话名称相同而合并不同旧记录，也不会自动删除历史。这个保守迁移仅带来单条内部去重和压缩，不能声称消除旧记录之间的重复内容；完成迁移前后磁盘占用可能增加。对新产生的响应，同一隔离范围内的块可跨响应复用。

确认全部运行实例都具备新格式读取能力，且已有独立恢复验证的完整备份，才能执行一批：

```sh
XHUB_DATABASE_URL="$YOUR_DATABASE_URL" go run ./cmd/history-compact --execute --confirm-no-legacy-writers --limit=50
```

工具打印 `migrated` 与 `next`；需要继续时将上一批 `next` 传给 `--after`。重新从空游标开始会跳过已迁移记录。运行中断或出错时保留旧副本；失败信息不包含正文或数据库地址。`--confirm-no-legacy-writers` 是操作人确认，不自动检测其他实例。旧版本继续写入时会让新副本过期，因此禁止在混合版本中迁移。该工具不清理旧记录或孤立内容块。

## 验收与回退

先在隔离环境验证中文、英文界面的请求流程，真实 PostgreSQL 的 JSON/SSE 续接、工具调用、身份隔离、并发、错误处理和迁移重跑；测量存储占用、写入/恢复耗时以及迁移过程的磁盘余量。测试上游使用合成数据，不需要生产凭据。合成样本节省率不代表线上效果。

发布时先让所有实例支持双格式读取，再决定是否启用新写入。关闭开关只能改变之后的写入；已经创建的新格式仍需要兼容读取，因此不能直接回退到不认识新格式的旧二进制。旧记录暂不删除。最终清理前需验证完整恢复、引用关系、空间预算和数据库维护方式；普通 PostgreSQL vacuum 主要回收可复用空间，不保证立即归还文件系统。
