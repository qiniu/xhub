## 目标与范围

让一次模型调用的解析、配置选择、单次上游尝试、响应输出、历史保存和结算各有明确归属，减少标准入口与 Bypass 的重复编排。用户仍使用原来的 URL、模型、Key 和会话；正常回复、错误、工具调用、流式结束、费用和历史续接应保持兼容。

保留 Go 模块化单体与现有目录结构。复用已有 `RoutePlan`、`RouteTarget`、`CallNote`、`ForwardResponse` 和宿主接口，先缩小职责，再决定是否需要新类型；不再引入一个包揽所有能力的通用执行框架。

固定范围为 P0–P6 七个工作包。新增协议、新模型能力、管理页面重做、数据库迁移、权限或预算规则调整不在本阶段。SSO 长期验收与供应商历史 issue 独立跟踪。审计发现的既有 Bug 单独登记，影响本批安全性时阻断对应批次，不默默改写既有业务语义或无限扩张阶段范围。

本阶段交付代码、真实测试、中文 PR 说明和证据清单。合并与部署仍单独决定；本方案不授权自动发布。进入架构实施前按仓库规范复用或建立带 `Architecture-Design` 的 Proposal，功能变化另外明确说明。

## 一次真实请求如何经过整理后的代码

以 `/v1/responses` 流式请求、随后用 `previous_response_id` 续聊为主线：

1. 入口完成现有鉴权，读取请求；保存原始载荷和解析结果，识别调用协议。客户端字段不能自行授予历史访问权限。
2. 恢复经过授权的历史，再按原顺序执行预算、护栏等检查。原生 Bypass 保留自己的既有治理边界。
3. 形成请求内的配置视图及路由计划，明确哪些字段固定、哪些运行时条件必须在尝试前重查。
4. 每次候选尝试执行原有模型/组授权、预算和连接归属检查。凭据解析仍按原有安全时点执行。
5. 协议适配器决定原生载荷或已支持的跨协议转换，transport 只执行一次上游调用并记录事实。
6. 执行器根据实际响应提交状态、协议终态和错误分类决定是否能重试；已经向客户端提交响应的请求不能盲目重放。
7. 历史保存、终态发布、日志与费用按既有顺序完成；资源释放覆盖成功、拒绝、取消和持久化失败。

原生与转换的选择以现有能力声明、历史和护栏约束为准。目标继续是支持的同协议路径保留原生、跨协议才转换，但本次重构不强行把所有同协议调用改成 Bypass，也不增加现有未支持的协议组合。

## 类型与状态设计约束

- 请求载体保存原始正文和只读投影；候选模型替换产生新载荷，不原地污染下一次尝试。multipart 不把文件转换成字符串。
- P1 的最小改动是给 `serveBypassCreate` 传入已解析载体，取代 `body/raw` 分开传递后重新解析。载体的导出名与最小方法在盘点调用方后确定，不为一个调用方新建包。
- `ForwardOfficial` 的测量输入必须反映实际出站内容；允许保留确有语义必要的解析，不以“全链路只解析一次”牺牲正确性。
- 配置视图不是冻结所有运行时状态。权限、预算、封禁、冷却、凭据与连接归属按现有读取时点复核；涉及改变热更新生效语义时另行提案，不夹带进重构。
- 请求级结果与单次尝试结果分开；至少区分收到上游头、向客户端提交头、输出正文、成功终态、取消/失败。复用现有字段或提供适配，不要求一步替换所有类型。
- 历史与任务归属不合并成通用缓存：Responses 父响应、Messages 签名引用、异步任务各保留自己的所有权、过期和连接绑定规则。
- transport 不决定预算、定价或跨目标回退；协议适配器不写身份库或自行结算；公共收尾不假设所有响应都已经成功。

## 不可改变的行为

1. 旧 URL、认证方式、响应包络、明确不支持状态及已覆盖的接口契约保持兼容。
2. 权限、预算、价格规则、缓存隔离、护栏启用范围保持；每次回退目标检查仍执行。
3. 未知供应商字段、精确数字、图片/工具/推理字段与签名不能在无转换必要时丢失。原生路径无改写时保留字节；必要改写只改变登记字段。跨协议按现有能力映射或明确拒绝，不能承诺任意未知字段可无损跨协议。
4. SSE 的原生事件顺序、换行和供应商扩展保留；转换路径验证协议语义与终态。TCP 结束不等于生成成功。
5. 已提交客户端响应、固定父响应及异步付费任务的不确定结果，按现有规则限制重放。`disable_fallbacks` 的既有语义保持。
6. 用量缺失、冲突和 pricing blocked 保持真实状态；不能用估算值冒充上游实测。费用、日志和历史的持久化顺序以基线为准。
7. 现有 70% patch 覆盖率门禁不降低；真实 regression 覆盖率继续采集上传。不得放大超时、隐藏首次失败或新增排除使 CI 变绿。

## 验证矩阵与证据

P0 将下列矩阵展开成固定条目，每条注明适用入口、已有测试、缺口、负责人批次和证据；不做无意义的全维度笛卡尔积。高风险交叉组合必须显式覆盖，例如“流开始后断连 + 回退配置”和“历史续接 + 连接凭据轮换”。

| 维度 | 必需场景 | 验证层与判定 |
| --- | --- | --- |
| 载荷 | JSON 未知字段/大整数/null/空值/非法输入；multipart 文件、模型、重复字段、错误 boundary；路径模型 | 单元检查确定性转换；真实 HTTP 上游检查收到的字段与文件字节 |
| 协议 | 已支持的 Chat、Responses、Messages、Gemini/Vertex 标准与原生路径；计数、embedding、媒体与异步操作按注册能力列出 | 本地协议上游 + 真实网关；未支持组合验证拒绝，不宣称支持 |
| 流 | 同步、流式、首字前失败、只发头后失败、部分内容后断流、无终态 EOF、终态后不关闭、客户端取消 | 断言真实响应、上游调用次数、取消传播、日志结果和资源释放 |
| 历史 | 双轮、工具调用后续、图片输入、父响应立即续接、越权/过期/连接失效、Messages 签名历史、并发迟到 | 真实 HTTP/数据库；自动浏览器覆盖可见续聊与错误恢复 |
| 路由 | 同部署重试、同池/跨池回退、禁用回退、固定父响应、异步创建、热更新、缓存命中 | 检查实际目标、调用次数、目标权限及预算，不能只断言 200 |
| 账务 | 成功、部分输出失败、无用量、冲突用量、缓存零推理费、计数、任务重复轮询、写入故障/恢复 | 查询真实日志和账务结果，断言既有结算规则与幂等行为 |
| 页面 | 登录后选择模型、双轮流式对话、历史恢复、错误可见、日志与用量查看 | Playwright → 真实网关 → 本地协议上游 → 隔离数据库；相关中英文路径 |

## 灰度、回退与完成条件

实现阶段保持可回退的小提交。影子对比只比较纯解析/计划结果，不能复制真实付费调用；不得把线上请求正文或密钥落入测试资料。

涉及执行行为的新旧实现切换，先核对已有灰度机制的覆盖范围；原生 Responses 灰度不能被假定覆盖整条执行链。只有确需运行时切换的批次才增加最小服务端开关并单独验收，不给每个纯函数增加长期双实现。

发布另行获授权后：测试环境组合验收 → 受控账号真实 GPT 同步/流式/工具/历史续接 → 核对日志和费用 → 再决定扩大范围。跨升级历史继续作为必测项。指标与观察窗口在 P0 基线和发布计划中确定；任一协议/权限/账务回归阻断放量，不等覆盖率兜底。

回退使用上一镜像或上一稳定实现配置，不清空会话、不回滚已产生账单、不重复创建任务、不切换数据库格式。要在隔离环境验证运行中的旧请求完成和后续新请求的行为。

固定清单中每项单独记录：待审计、已有验证、待补测试、待修复、明确不支持；另列提交、CI、合入和部署状态。七包都有证据且组合验收通过，才称“第五阶段开发完成”；合并、部署、真实外部验收分别报告，不能相互替代。

每批证据建议保存 `.verification/phase5/P<n>/`，包含 `report.md`、测试原始事件、汇总、覆盖率与清理结果。最终报告还要列出删掉了哪些重复实现、还保留哪些有业务原因的分支。
