# 模型监控设计

监控按供应商连接与实际上游模型统计；相同别名合并到同连接的实际模型。供应商身份优先使用凭据连接名，内联地址移除认证信息及查询参数。下拉目录来自授权部署配置，并合并可见历史记录，不依赖查询窗口内是否有调用。

## 写入与查询

账单与监控桶在同一 PostgreSQL 事务提交。账单幂等插入成功后才累计统计；任务结算减去旧值、加上新值。请求先进入现有 Redis 账单队列，监控在账单落库后可见，存在刷盘周期的延迟。

15 分钟 UTC 桶保留组织、团队、项目、用户、密钥、计费归属、供应商及实际模型维度。批次内相同桶先合并，再按稳定键序执行增量 UPSERT，减少数据库操作及并发锁冲突。查询只读预聚合桶，使用时间及授权维度索引，不扫描 usage_events。单条 GROUPING SETS 查询返回汇总、模型明细与日趋势，保证同一快照。窗口限制 1 至 90 天，时区偏移按 15 分钟对齐。

开销随不同维度桶数增长；精细授权维度意味着高基数用户及密钥仍会增大存储和查询量。热点桶存在行锁竞争。测试验证 5000 条同维度记录压缩为 1 桶，未进行生产规模负载基准。

## 性能口径

TTFT 记录首个上游响应字节或数据段的耗时，可能只是元数据，不保证等于首个可见文本 Token。TPS 使用**输出 Token** × 1000 /（总耗时毫秒 − 首字节耗时毫秒），仅成功、非缓存、输出为正且生成区间有效的流式文本请求计入样本。输入 Token 不参与生成速度；同步响应的读尾时间不能表示模型生成区间，因此无 TPS 样本。跨桶均值按有效样本数加权，请求数、Token 与费用仍汇总全部已记录的终态请求。

启动升级在与账单写入共用的事务中，根据仍保留的原始用量事件一次性重建输出 TPS。新指标列与旧口径独立，避免旧版本写入污染修正后的速度；仅修正 TPS 累加和与样本数，不改写账单、费用、请求数、Token 或其他指标。原始事件已清理的桶保留原有统计但显示无 TPS 样本。完成标记保证重复启动幂等；修正失败整体回滚并拒绝启动。
